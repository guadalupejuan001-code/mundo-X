# Mundo X / Cosmic PC: 8042 tras el arranque ISO real

## Observación de Android

El usuario arrancó su ISO oficial de Windows 10 en el motor
\`cosmic-pc-own-x86\`, y la CPU llegó a \`2000:0ACE\` tras **2.791 pasos**
y **21 lecturas BIOS**. La instrucción que detuvo el programa fue
\`E6 64\`, equivalente a \`OUT 0x64, AL\` (valor del puerto 100 en decimal).
El indicador \`real16\` corresponde al cargador BIOS, no al kernel de
Windows 10. En esa ejecución la app registró **69 MiB PSS**; no es la RAM
mínima de Windows 10 ni una prueba de que el instalador funcione.

El valor de AL no aparece en la captura, así que **no está demostrado**
qué comando 8042 envió la ISO del usuario. No debemos asumir 0xD1 sin
leer su registro de CPU completo tras volver a probar.

## Corrección con semántica

Antes de este cambio, el PC ya respondía a \`IN 0x64\` con cero, pero
rechazaba todos los comandos \`OUT 0x64\` y la comunicación \`0x60\`.
Eso no equivalía a un controlador de PC.

\`Pc8042\`, acoplado a la máquina existente, implementa un subconjunto
real del controlador PC/AT:

| Puerto / operación | Semántica |
|---|---|
| \`IN 0x64\` | Estado: output buffer (bit 0), input buffer instantáneo (bit 1 = 0), bandera POST (bit 2), último tipo de escritura (bit 3) |
| \`IN 0x60\` | Extrae una respuesta de un byte; lectura vacía aproxima bus abierto con 0xFF |
| \`OUT 0x64, 0xD1\` + \`OUT 0x60, valor\` | Escribe el puerto de salida; bit 1 controla la línea A20 real de la CPU |
| \`OUT 0x64, 0xD0\` + \`IN 0x60\` | Lee el puerto de salida actual y observa también cambios de la puerta rápida A20 (0x92) |
| \`OUT 0x64, 0x20 / 0x60\` | Lee/escribe byte de configuración; cambios en reloj teclado no generan IRQ ficticias |
| \`OUT 0x64, 0xAD / 0xAE / 0xA7\` | Deshabilita/habilita primer puerto o deshabilita segundo, sin afirmar que exista mouse |
| \`OUT 0x64, 0xAA / 0xAB\` | Respuestas acotadas 0x55 / 0x00 para autopruebas |

Las solicitudes de reset del procesador, comandos de dispositivo
sin controlador, señales IRQ1/IRQ12, mouse y otras funciones 8042
**siguen sin estar implementadas**. El motor se detiene con un error
que ahora incluye **el valor del comando**. No se emulan por omisión.

La referencia física del A20 se mantiene en \`Cpu::a20_enabled\`;
no se crea un segundo estado contradictorio dentro del teclado.

## Verificación

\`pc-android/native/tests/pc_8042_test.cpp\` comprueba:

- Puerto 0x64 como registro de estado y comandos; 0x60 como registro
  de datos y respuestas.
- Activación y desactivación A20 con 0xD1/0xD0, coherentes con 0x92.
- Autoprueba, máscaras del teclado, bytes pendientes, reset, fallos
  explícitos ante operaciones desconocidas y no reinicio silencioso.
- ISO sintética El Torito real, iniciada en \`CS=2000, IP=0000\`,
  cuyos bytes saltan exactamente a \`2000:0ACE\`, ejecutan
  \`E6 64\` y \`D1/DF\` y llegan a \`HLT\`.
- La misma secuencia se ejecuta en Android mediante JNI y el motor
  C++ original en la instrumentación \`WindowsInstrumentation\`.

Se trata de **un reproducer** de la dirección y del opcode, no de
la ISO propietaria del usuario. Solo repetir la ISO del usuario en
su teléfono permite medir cuál es la siguiente barrera verdadera.

## Reprobar en el celular

1. Instalar la nueva APK \`MUNDO-X-WIN10-ISO-LAB 0.1.1\`.
2. Elegir la ISO oficial desde el selector Android (solo lectura).
3. Presionar \`Arrancar BIOS (ISO)\`.
4. Copiar diagnóstico completo. Comparar pasos CPU, \`CS:IP\`,
   último comando 8042 y motivo de parada con el registro anterior:
   2.791 pasos, 21 lecturas de disco, \`2000:0ACE E6 64\`.

**No se afirma ejecución de Windows 10 completo.** Faltan UEFI,
instrucciones como SSE2, dispositivos ACPI/APIC, IRQ protegidas,
almacenamiento de escritura y drivers. La mejora se limita al
protocolo físico 8042 alcanzado por el bootloader.
